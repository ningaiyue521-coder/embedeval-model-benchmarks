# 评测与测量方法

## 冻结条件

- 上游：`Ecro/embedeval`，提交 `fdbcb9b93476149cce2d395532bf5164811fe053`。
- 219 个公开基础案例，经参考答案通过、种子缺陷触发预期失败的筛选，导出 614 道 Bugfix 变体。多个变体可来自同一基础案例，并非 614 个独立工程任务。
- 原始题面及 Bug Hint 原样保留，存在提示信息；不是无提示仓库级修复。
- 每个模型、档位、题目使用新的 Codex CLI 临时会话；普通档位的候选指令禁止文件访问、运行代码、外部资料与工具调用。原始指令见 [protocols.json](../data/protocols.json)。
- 首轮 Ultra 明确允许原生子模型协作，但同样禁止读取文件、外部工具与评分反馈。不能假定每份 Ultra 答案都实际调用了子模型。
- 模型名称与档位是测试当天运行器记录的标识，不表示服务端内部版本永久固定。

## 一次作答

唯一键为 **实验轮次 + 模型 + 档位 + 题目**。该轮只保留首次完整最终答案，不把评分反馈发回模型，不补问、不修改答案提分。10 题试跑后，用户另行要求新会话开始 614 题轮次；不同轮次答案独立保存，没有挑选较高分版本。

3,750 份答案在原始本地记录中具有不同的会话标识；导出时核对了原始答卷、提示哈希、评分哈希与尝试记录。发布包不含会话标识与传输日志，因此可公开复现的是文件完整性和评分，而不是独立证明服务端行为。`results/export-audit.json` 是本地核验记录，不是第三方认证。

完整 Low 批次未人工或通过运行器重新调用同一题。Luna 初期出现本地记录故障：一个已确认尚未启动模型的占位被释放，四份已保存答案仅补做本地评分。没有让模型重答。

**一次 CLI 调用不等于一次网络请求。** 客户端内部出现过自动重连或传输回退：Luna Low 133 题，三模型 Low 合计 946 题，5.6 Sol Low 304 题，暂停 Xhigh 129 题。所有纳入结果的调用最终给出完整答案。token 统计来自完成回合，可能不覆盖所有失败传输活动。

## 评分

2026-11-06 补齐批次允许对限流等传输失败且尚无最终答案的题目补发；已产出的首答始终锁定，不根据评分重答。该批次共 9 组、5,526 份首答，完整性核验后以相同冻结 L0/L3 规则重评；[批次报告](../results/missing-nine-tiers-20261106.md)列出新增成绩。

固定运行上游 L0 静态检查，只有 L0 通过后才运行 L3 启发式规则检查。某一题需要该流程的全部检查通过才算通过。失败不是部分给分；评分器异常不算通过，也不作为已完成成绩发布。

- 首轮 10 题：`10 × 通过题数`。
- 全量 614 题：`100 × 通过题数 / 614`，保留两位小数。
- 未满 614 题的组合：`score = null`，只公布完成数与通过数。

没有进行 L1 编译、L2 运行或仿真、L4 完整判题器变异验证。评分器直接检查源码文本，不执行候选代码。已发现屏障、消抖参数、资源清理路径与 volatile 等误判，见 [具体证据](grader-limitations.md)。原始分全部保留，未按人工判断追改。

## 耗时与 token

`cliSeconds` 来自原始 Windows 事件文件创建至最后写入的间隔，包含客户端启动与网络传输，排除后续本地评分；导出时保留测量值，不能用下载后的文件时间重算。平均值、P95 等采用原始汇总报告。

`secondsIncludingGrading` 包含单题调用和本地评分。并发运行时，这些时间相加不等于整轮墙钟时间。Luna 并发从 4 逐步升至 64，三模型 Low 共享 64，5.6 Sol Low 单独使用 64；机器负载、缓存、重连和并发分配影响比较，墙钟时间不是纯模型推理速度。

`input_tokens` 包含 `cached_input_tokens`，`output_tokens` 包含 `reasoning_output_tokens`，不要重复相加。只公布推理 token 数量，不公布推理文本。账户用量百分比是共享且取整的记录，包含控制任务或其他账户活动；没有按 API 单价估算订阅费用。

## JSONL 字段

每行是一份首次最终答案，可用 Python `json.loads(line)` 读取。

| 字段 | 含义 |
|---|---|
| `round / model / effort / caseKey` | 唯一尝试标识 |
| `ordinal / caseId` | 本轮题序与上游变体 ID |
| `firstAnswer / answerHash` | 完整最终答案文本与 UTF-8 SHA-256 |
| `promptHash / rulesHash / revision` | 冻结题面、检查器及版本关联 |
| `checks` | 实际执行的逐项规则结果，保留 expected 与 actual |
| `passed` | 本题固定流程是否全部通过 |
| `tokens` | 完成回合的 token 计数 |
| `transportWarning` | 本地日志是否记录传输重连或回退 |

文本读取保留答案内容，按原评分器的通用换行方式归一为 LF；哈希基于该 UTF-8 文本。上游 `rulesHash` 当时基于 Windows CRLF 工作树字节，安装脚本在固定版本的 Python/YAML 文件上恢复相同换行并检查全部 614 个哈希，未更改检查逻辑。发布包是白名单导出，不包含原始数据库、账户快照、进程信息、绝对本机路径或网络日志。
